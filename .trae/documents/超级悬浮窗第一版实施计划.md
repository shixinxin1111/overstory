# 超级悬浮窗第一版实施计划

## 概要

在当前空工作区创建一个面向个人日常使用的 macOS 桌面应用，暂名 **Overstory**。采用 **Tauri 2 + React + TypeScript**，UI 全部手写，使用 **Motion** 实现精致、有触感的丰富动效。视觉参考现代苹果／macOS：清透材质、细腻高光、清晰秩序，整体酷炫但不杂乱。支持“小球、悬浮面板、普通主窗”三种互斥形态，第一版提供待办、常用网页管理和便签。

交付完整源码、开发说明和当前 Apple Silicon Mac 可运行的 `.app`。本阶段只制定计划，用户批准后开始实施。

## 用户体验与窗口规则

### 三种形态

| 形态 | 初始尺寸，逻辑像素 | 行为和布局 |
| --- | --- | --- |
| 小球 | 56 × 56 | 无边框、透明底、置顶，可拖动；显示未完成待办数，超过 99 显示 `99+`，零项显示 `0` |
| 悬浮面板 | 380 × 520 | 置顶；固定工具栏和模块入口，内容区独立滚动；支持调整窗口尺寸 |
| 普通主窗 | 1040 × 720 | 普通窗口层级，保留 macOS 原生标题栏、关闭／最小化／缩放操作；侧边模块导航与完整内容区 |

- 第一次启动显示小球，放在主显示器工作区右侧中部，距边缘 24px；后续恢复退出前的形态和各形态几何信息。
- 单击小球展开最近使用的模块；初次默认进入待办。
- 小球拖动位移超过 5px 后按拖动处理，松开不展开。拖动使用原生窗口操作；面板仅工具栏空白区域可拖动，输入、文本选择和按钮不能触发拖窗。
- 面板工具栏提供“切换主窗”“收起”“设置”；按 Esc 收起面板，但有弹层时先关闭弹层，中文输入组合期间不收起。
- 主窗提供“收回小球”；原生关闭按钮同样收回小球。最小化、缩放按普通软件行为处理，主窗按 Esc 不改变形态。
- 面板失焦始终保持展开；小球／面板置顶，主窗不置顶。
- 小球右键菜单提供“展开面板”“打开主窗”“退出”；Dock 再次打开应用时呼出主窗。
- 窗口切换保留当前模块、选中的便签／网页分组、筛选、搜索和滚动位置，不清空正在编辑的内容。
- 分别保存小球位置、面板尺寸／锚点、主窗尺寸／位置。使用逻辑坐标并记录显示器信息；启动、切换和显示器变化时按当前工作区约束位置，避免窗口落到屏幕外。首次面板在小球内侧展开，随后使用用户调整的面板位置。
- 悬浮窗口使用 Tauri 跨工作区能力；不同 Spaces、系统全屏场景需在原生应用中验证实际行为。

### 三项功能

**待办**

- 新增、编辑标题、删除、勾选完成和恢复未完成。
- 提供“全部／未完成／已完成”筛选；默认显示未完成，列表使用持久化的手动顺序。
- 每项前方提供拖拽锚点；在完成状态筛选中可调整可见项目的顺序，隐藏项目的相对顺序保持不变。完成／恢复不改变该项的手动位置。
- 标题去除首尾空白，空标题不能提交；中文输入期间 Enter 不误提交。
- 小球数量由同一份待办数据派生，不另外维护计数。
- 删除用轻量确认，空列表显示具体空态和新增入口。

**常用网页**

- 管理网页标题、URL 和所属分组；支持新增、编辑、删除。
- 支持分组新增、改名、删除；始终保留“未分组”，不能删除但可以排序。删除分组时网页按原顺序追加到未分组，不连带删除。
- 全部分组和分组筛选，按标题／URL 搜索；分组与组内网页均使用持久化的手动顺序。
- 网页与分组标题前方都有独立拖拽锚点。网页可在组内换位或拖入其他分组；分组拖动时整体移动，不改变组内网页顺序。
- 无协议的域名补全 `https://`；只接受有效 HTTP/HTTPS URL，拒绝其他协议。
- 点击打开按钮，交由系统默认浏览器打开；选择列表项与打开操作分离，不在应用内嵌网站，也不主动抓取网站内容或图标。
- 搜索无结果和尚未收藏网页分别展示不同空态；使用手写 SVG 图标，不依赖外网图片。

**便签**

- 多篇便签；标题与纯文本正文编辑、新增、删除，按标题／正文搜索。
- 支持便签分组新增、改名、删除；“未分组”不可删除但可排序。删除分组时便签按原顺序追加到未分组，不删除正文。
- 便签与分组均使用持久化的手动顺序，通过前方锚点进行组内、跨组和分组排序；编辑标题、正文或自动保存都不改变位置。
- 新便签显示“未命名便签”，正文可以为空；新增条目追加到当前组末尾，“全部”视图中默认加入未分组。
- 主窗使用分组便签列表加编辑区；面板使用紧凑分组列表／编辑视图，返回列表仍保留选中项。跨组移动选中便签时仍保持编辑对象，不重建编辑器或清空草稿。
- 输入即时回显，250ms 防抖自动保存；切换便签、模块、窗口形态、导入导出和退出前强制提交待保存内容。
- 保存状态固定占位，区分“保存中／已保存／保存失败”；失败保留草稿，提供重试，不能回显为已保存。

**设置**

- 只提供“小球显示待办数量”开关、导入和导出。
- 设置是应用壳的入口，不与三个业务模块重复注册。
- 隐藏数字时显示简洁圆形符号，球尺寸保持不变。

### 锚点拖拽、跨组移动与导航排序

**统一交互**

- 所有可排序行前方使用同一手写点阵锚点，锚点始终占据稳定宽度，默认低对比，悬停／聚焦时清晰；可点击区域不小于 24 × 32px。
- 只能从锚点开始拖拽，位移超过 5px 才进入排序。按正文、勾选框、编辑框、打开按钮或分组折叠按钮都不触发排序，不使用整行可拖动。
- 使用手写 Pointer Events 拖拽控制器和 Motion 位移／布局动画，不引入拖拽组件库。列表排序不使用原生窗口拖动 API。
- 拖动时显示轻微抬起的跟随副本，来源保留等高占位；目标使用一条系统蓝插入线，其他行弹性让位。仅改变预览，松开到有效目标时提交一次数据操作。
- 支持滚动容器边缘自动滚动，速度随边缘距离变化；仅在拖拽期间通过 requestAnimationFrame 工作。结束、取消、窗口失焦或卸载后释放指针捕获与滚动任务。
- Esc 取消拖拽，拖拽中先消费 Esc，不收起面板。指针取消、释放到无效区域、关闭窗口或切换模块／形态时取消未提交拖拽，恢复原顺序。
- 保存失败回滚到最后已保存的顺序并显示错误，不留下“看似已经移动”的假状态。
- 锚点可通过键盘聚焦，Space／Enter 拾起、方向键换位；有分组时 Left／Right 选择目标组，Space／Enter 放置，Esc 取消。导航拖动按其水平／垂直布局处理方向键，提供简短屏幕阅读器播报。

**分组展示与跨组目标**

- 网页列表和便签列表在“全部”视图按分组顺序展示可折叠分组区段，组标题前是分组锚点，项目行前是项目锚点。
- 分组标题可接收项目，放到组标题或空组区域时追加到该组末尾；放到某项前后的插入线时落到指定位置。悬停折叠组标题 350ms 后临时展开，结束后恢复原折叠状态。
- 分组筛选视图仍保留顶部组选择器；拖动项目悬停该选择器 350ms 时展开全部分组作为目标，放到目标组行时追加到该组末尾，方便移动到当前不可见的组。
- 项目只能在同一模块的分组间移动，不能把网页拖成便签。分组只能与同一模块的其他分组换位，不能拖进另一分组形成嵌套。
- 新增分组追加到末尾，新项目追加到所属组末尾。相同位置放置视为无操作，不发送重复保存请求。
- 待办仍为单列表，不额外增加待办分组；完成状态过滤只改变可见性，不建立完成／未完成两个可移动的业务分组。

**导航与过滤**

- 主窗纵向模块导航与面板横向模块入口都提供前方锚点，顺序共用 `preferences.moduleOrder`。导航换位不切换当前模块，手柄点击也不触发模块选择。
- 模块注册表中的 `order` 仅作为初始默认顺序；以后新增模块按默认顺序追加到尚未配置的入口末尾。
- 搜索关键词非空时，该业务列表及其分组锚点显示禁用状态，旁边提示“清空搜索后可排序”；不改变原排序。模块导航仍可排序。
- 无搜索关键词的待办状态筛选或单组筛选可以拖拽。过滤列表在可见目标前／后插入被拖项，完整列表中其他项目的相对顺序不变，不将过滤结果整表覆盖。
- 拖拽过程中的跨组预览不提前改变当前筛选；提交后若项目不属于当前筛选，则从列表移出，并显示目标分组的简短反馈。

## 技术架构

### 窗口与应用壳

创建两个长期存在的 WebviewWindow：

1. `floating`：小球和悬浮面板复用，动态切换尺寸／内容，透明、无装饰、置顶。
2. `main`：带原生装饰的普通窗口，初始隐藏。

使用 Rust `WindowController` 管理 `orb | panel | main` 状态和转换。两个窗口共用前端构建，由窗口 label 选择应用壳。普通主窗保留原生能力，避免反复重建 WebView。

转换统一执行：

1. 将请求串行化，重复点击不会并发改变窗口。
2. 要求当前可见渲染器提交草稿和会话状态，收到成功确认后继续。
3. 按下时立即给出触感反馈；准备目标几何和内容，并协调出场／入场动画。跨原生窗口转换时先隐藏来源，再显示并适当聚焦目标；最多一个窗口可见。
4. 更新当前形态及几何持久化。失败时恢复原窗口并显示具体错误。

原生主窗关闭请求先阻止默认销毁，再走同一转换流程；退出同样先提交草稿。保存失败或渲染器未完成交接时保留来源窗口，允许重试，不能静默丢弃内容。球模式不主动抢占其他应用输入焦点。

小球／面板转换采用同一 WebView 内的动画状态 `orb → opening → panel → closing → orb`。展开时先一次性调整原生窗口到目标尺寸，再按小球锚点动画显示面板；收起时先在现有尺寸内完成内容退出和小球回收，再将原生窗口缩回 56 × 56。动画仅驱动内部视觉，不逐帧请求 Rust 改变窗口边界。转换期间保留下一次目标请求，以最后一次操作为准，取消旧动画后平滑转向，避免重复点击造成卡死或排队播放。

### 模块扩展接口

前端定义统一 `ModuleDefinition`：

```ts
type ModuleDefinition = {
  id: string;
  title: string;
  icon: React.ComponentType;
  order: number;
  dataVersion: number;
  View: React.ComponentType<{ presentation: 'panel' | 'main' }>;
  getOrbSummary?: (snapshot: AppSnapshot) => string | number | null;
};
```

- 注册表负责模块导航、视图加载和摘要能力，结合用户保存的 `moduleOrder` 生成两个窗口的相同入口顺序，应用壳不写待办／网页／便签分支逻辑。
- 同一业务 View 通过 `presentation` 调整布局；复用业务操作、数据和校验。
- 第一版固定选用待办摘要，保持用户选择；可选摘要接口为未来模块留入口。
- 每个模块拥有自己的目录、数据类型和 Rust 操作处理器。新增模块需增加模块文件并注册前后端处理器，无需重写窗口管理器。
- 后端模块存储采用带版本的命名空间 JSON，模块处理器使用各自的 Serde 类型进行校验和迁移。不引入外部插件加载或脚本执行系统。

### 本地数据与接口

Rust 持有唯一权威数据；React 不将 localStorage 作为业务存储。使用 Tauri 标准应用数据目录，通过 `app_data_dir()` 获取位置。

数据文件 `state.json`：

```text
schemaVersion: 1
revision: number
modules:
  todos:     { version: 1, data: { items: Todo[] } }
  bookmarks: { version: 1, data: { groups: Group[], items: Bookmark[] } }
  notes:     { version: 1, data: { groups: Group[], items: Note[] } }
preferences: { showTodoCount: boolean, moduleOrder: string[] }
windowState: { mode, orbPosition, panelBounds, mainBounds, monitorInfo }
session: { activeModuleId, selectedNoteId, selectedGroupIds, todoFilter }
```

业务字段：

- `Todo`：`id, title, completed, sortIndex, createdAt, updatedAt`。
- `Group`：`id, name, sortIndex, createdAt`；“未分组”使用模块内固定 ID。
- `Bookmark`：`id, title, url, groupId, sortIndex, createdAt, updatedAt`。
- `Note`：`id, title, content, groupId, sortIndex, createdAt, updatedAt`。
- `sortIndex` 为非负、连续整数，待办在完整列表内排序，网页／便签在组内排序，分组在模块内排序；跨组操作重新归一化来源和目标两组的索引。
- ID 由后端创建为 UUID；时间统一为 UTC ISO 8601，只用于记录，不再决定展示位置。
- `selectedGroupIds` 按模块分别记录网页和便签选中分组；折叠状态在两窗切换时交接。
- 初始模块顺序为待办、网页、便签。`moduleOrder` 使用稳定模块 ID，重复 ID 不允许；新模块追加，暂不识别的模块 ID 保留在存储中但不渲染。
- 会话中的搜索、滚动、编辑草稿通过切换交接在两窗口间传递；搜索和滚动不需要每次输入写磁盘。

Tauri commands：

| 接口 | 职责 |
| --- | --- |
| `get_snapshot` | 获取已初始化的业务数据、设置、形态和选中状态 |
| `execute_module_action` | 按模块处理增删改／完成、分组管理、项目和分组移动，后端校验并持久化 |
| `update_preferences` | 保存小球数量开关和模块导航顺序 |
| `request_presentation` | 请求切换形态，统一走草稿交接流程 |
| `acknowledge_transition` | 确认草稿已提交并交接会话状态 |
| `request_quit` | 保存后退出 |
| `open_bookmark` | 后端再次校验 URL，交给系统默认浏览器 |
| `export_backup` / `import_backup` | 原生文件选择、备份导出／恢复导入 |

- 成功修改返回带 revision 的快照，并广播 `app:snapshot-changed`。前端先订阅再获取初始快照，仅接受不旧于当前 revision 的数据，避免初始化竞争和重复回显。
- 修改只发送对应模块的操作，不由任一窗口上传整份旧快照覆盖其他数据。
- 排序使用 `move_item { itemId, toGroupId?, beforeItemId: string | null, expectedRevision }` 与 `move_group { groupId, beforeGroupId: string | null, expectedRevision }`；`null` 表示追加，前端将“放在某项之后”转换为其下一项 ID。待办不提供 `toGroupId`。
- 跨组修改 `groupId` 与来源／目标索引在同一候选状态和一次原子写入中完成；后端验证项目、目标组、锚点、归属与 revision。过期请求返回明确错误并刷新快照，不使用旧数组覆盖新操作。
- 便签拖拽提交前完成当前草稿 flush，以最新 revision 发起移动；拖动的预览不触发便签切换或文本重新挂载。导航排序同样在最新状态上只修改 `moduleOrder`。
- 后端在串行写入锁中校验候选数据、写同目录临时文件、同步并原子替换成功后，再提交内存状态和 revision。
- 保存前保留上一份有效数据为 `state.last-good.json`。首次没有文件才初始化空数据；损坏数据不得直接当作空态覆盖，尝试恢复有效副本并提示，无法恢复则保留原件进入可恢复的错误状态。
- 错误统一返回 `{ code, message }`，区分校验、写入、导入格式、窗口转换和外部打开失败。界面中的“已保存”必须以持久化成功为准。

### 备份恢复

- 导出 JSON 使用 `{ format: "overstory-backup", schemaVersion: 1, exportedAt, modules, preferences }`，包含分组和全部手动顺序，不包含窗口坐标和临时编辑会话，便于恢复到不同屏幕。
- 导入采用“覆盖恢复”，不做合并。原生文件选择后先解析并展示各模块记录数量，用户确认覆盖才执行。
- 导入前完整校验类型、版本、唯一 ID、URL、分组引用、排序索引和模块导航顺序；非法或未来不支持的版本不能修改现有数据。
- 当前工作区没有已发布应用或历史数据，第一版的数据格式直接包含分组和排序字段；保留版本校验与未来迁移入口。
- 覆盖前创建带时间戳的自动备份；写入失败时原数据保持有效。成功后广播新快照并修正已经不存在的选中项。
- 保留暂不识别的模块命名空间，避免以后使用旧版应用恢复备份时损失未来模块数据。
- 用户取消文件选择或覆盖确认视为正常取消，不报错误。

### 外观与基础组件

- 所有 UI 使用手写 React 组件、原生 HTML 语义和 CSS。Motion 只负责动画，不提供界面组件；不引入组件库、现成 headless 组件套件或图标库。
- 共用组件包括 `Button`、`IconButton`、`TextField`、`Checkbox`、`SegmentedControl`、`ContextMenu`、`Dialog`、`Toast`、`EmptyState`、`DragHandle`。只实现三个模块确实需要的能力，不建设通用组件库。

- 使用系统主题监听同步两个 WebView 的浅深主题和 CSS tokens，不增加额外主题切换功能。
- 工具栏、模块导航和保存状态占位固定，切换模块／状态时容器稳定。滚动条靠内容区边缘，不盖文字。
- 手写弹层使用 React Portal，在当前窗口内进行焦点管理、焦点恢复、Esc 关闭和点击外部关闭。确认对话框锁定背景交互；菜单支持方向键、Enter 和 Esc，复选框支持 Space。列表、输入、按钮和空态有键盘焦点及可访问名称。

### 苹果风格的视觉规范

设计方向为精致的桌面工具：小球是视觉记忆点，展开过程体现科技感，面板和主窗提供有秩序的工作区。参考苹果对材质、排版和动作的处理，不使用苹果商标或现成系统界面截图。

| 区域 | 视觉设计 | 信息秩序 |
| --- | --- | --- |
| 小球 | 近似抛光玻璃／金属的小物件，圆形内高光、柔和明暗和一处微弱蓝色反光；数量清晰居中 | 保持一个数字或符号，材质细节不压过内容 |
| 悬浮面板 | 20px 圆角，高不透明度的半透明表面，内侧细高光；外层只保留一层轻微投影 | 固定工具栏、紧凑模块导航、单一内容区，按对齐和间距划分层级 |
| 主窗 | 保留原生 macOS 标题栏，中性背景、低对比侧边导航、清楚的编辑区 | 每屏一个主要内容区；业务操作就近放置，不叠加装饰性概览或大标题 |
| 基础控件 | 圆润按钮与输入框，分段导航有轻微立体感；图标统一手写细线 SVG | 同类控件同尺寸，文字与图标对齐，主操作使用系统蓝 |
| 选中与焦点 | 柔和蓝色选中底，明确焦点环；悬停有少量亮度变化 | 选择、悬停、完成和禁用具有独立可辨的状态 |

具体实现：

- 浅色底 `#F5F5F7`、正文 `#1D1D1F`、次级文字 `#6E6E73`、强调 `#007AFF`；深色底 `#171719`、正文 `#F5F5F7`、次级文字 `#A1A1A6`、强调 `#0A84FF`，全部集中为 CSS tokens。
- 玻璃和金属感通过半透明表面、静态低对比渐变和内高光表达。材质集中于小球、面板外壳和导航；正文列表与便签编辑区域保持接近不透明的平静底色，不让桌面背景影响阅读。
- 视觉层级固定为“一个外壳＋导航／工具栏＋内容”，使用间距、底色和细分隔建立秩序；常规列表不套多层卡片。
- 间距使用 4px 网格，核心间距为 8／12／16／24px。正文 14px，辅助信息 12px，模块标题 17px；数字采用等宽数字特性，计数变化不横向跳动。
- 控件圆角 10px，内容分区圆角 12px，面板 20px；小球保持正圆。基础图标统一 1.5px 线宽；图标按钮 32px，普通列表行约 36–40px，保持紧凑且容易点击。
- 投影只承担悬浮层级提示，列表和常规控件不各自叠加阴影。边缘高光、选中状态和轻微反光体现精致感，不使用大面积霓虹、彩虹渐变或背景纹理。
- 浅深主题均单独调整表面、边缘、文字对比和高光强度；深色主题不通过整屏外发光体现酷炫。
- 悬停小球时高光做一次很短的位移，配合弹性按压增强触感；不持续扫光。其他材质不随每次输入或鼠标移动重绘。
- 设计验收同时检查静态截图和真实操作：静止时干净，操作时有记忆点，任务与文本始终容易阅读。

### 丰富动效与触感

明确采用“精致弹性、有触感”的气质：轻微回弹、连贯的形态过渡和细节反馈，与苹果风格的材质和层级保持一致。小球展开／收回是核心动作，其余动效服务于用户正在进行的操作。小球静置时保持安静，避免不停跳动或持续消耗资源。

| 交互 | 动作设计 | 时间与边界 |
| --- | --- | --- |
| 小球悬停／按压 | 悬停轻微放大并触发一次内高光移动，按下压缩；释放时轻微回弹，数字位置稳定 | 悬停约 100ms，高光约 180ms，按下立即响应；缩放约 1.04／0.94 |
| 展开／收回面板 | 以球位置为视觉锚点，圆形轮廓、数量和面板内容接续过渡；内容分两组短错峰入场 | 主动作约 260–320ms；组间约 20ms，球与面板不留跳切空白 |
| 面板／主窗转换 | 相同模块内容短淡出／入场，保持编辑状态；主窗从轻微位移和透明度过渡进入 | 约 180–220ms，不模拟跨两窗口的连续变形 |
| 模块切换 | 活动导航指示随目标滑动，内容轻微方向移动与透明度过渡 | 约 160–200ms；目标内容立即接收操作，容器高度不变 |
| 按钮与图标 | 按下约 0.97 缩放，释放回弹；悬停仅在颜色和位置上给出细微反馈 | 按下立即响应，释放约 120–180ms |
| 待办完成／恢复 | 勾选路径绘制、文字色彩与划线同步变化；在未完成筛选中短退出，并让其他行平滑补位 | 主反馈约 180–240ms；退出不会延迟后端提交 |
| 待办数量变化 | 数字在固定区域短距离滚动／淡入，增减方向可辨，零项与 99+ 尺寸一致 | 约 160ms，不使球体抖动或改尺寸 |
| 列表新增／删除 | 新项立即插入，再短距离进入；删除项淡出，其他行补位 | 约 160–220ms；不让整张列表重复入场 |
| 拖拽排序／跨组 | 锚点激活，跟随副本轻微抬起，目标插入线清晰，邻项弹性让位；放置时柔和落下 | 跟随指针即时更新，让位／落下约 160–220ms；不依赖动画结束保存 |
| 网页打开 | 打开图标短距离向外移动后复位，确认已触发操作；错误显示具体提示 | 约 140ms；实际打开立即调用，不等待动画 |
| 便签选择／保存 | 选中条移动，编辑内容短过渡；保存成功提示短显；持续输入区域不跟随重播动画 | 约 120–160ms；保存状态固定占位 |
| 菜单／对话框／提示 | 从触发点轻微缩放与淡入，退出简短；焦点状态同步 | 入场约 140–180ms，退出约 100–140ms |

实现约束：

- 使用 `motion/react`、`AnimatePresence`、`LayoutGroup`、motion values 和 `useReducedMotion`；动画与业务持久化流程解耦。
- 在 `src/shared/motion.ts` 集中维护反馈、内容和形态三档预设，初始弹簧分别使用 stiffness/damping/mass `500/35/0.65`、`380/30/0.8`、`320/28/0.9`，只允许小幅回弹。实际视觉验收时在这三档预设内统一调整，不在各组件散落参数。
- 优先动画 `transform`、`opacity` 和 SVG 路径；圆角形变仅用于小球转换。列表布局动画限于受影响行，使用 FLIP，不逐帧改变整个编辑区域尺寸。
- 高速操作允许中断和转向；内容点击、IPC 调用、键盘输入不等待装饰动画结束。错误、取消、空数据和大数量下也有完整终态。
- 每个动作中的淡出、位移、数字和指示条共用节奏，不同时播放多个无关庆祝效果；不加入声音、粒子、磁吸鼠标或重模糊。
- 输入法组合、文本选择、滚动和原生拖动优先，不能被动画手势截获。
- 开启系统减少动态效果时去掉弹跳、位移和数字滚动，保留不超过 100ms 的必要透明度反馈；操作含义和终态相同。
- 隐藏窗口及小球静置时不运行循环动画，业务更新不重新播放整个模块入场动画。
- 拖拽副本的指针跟随使用 motion values，不能每帧更新完整 React 列表；碰撞区缓存，在滚动／布局变化时更新。行让位动画使用集中预设，不与原生拖窗或文字选择竞争。

| 默认启动 | 小球真实悬浮在桌面，数字来自真实数据 |
| 拖动／点击 | 点击展开；拖动后松开不误展开，重启位置恢复 |
| 三态切换 | 连续操作只有一个形态可见，主窗是真正普通窗口 |
| 面板失焦 | 点击其他应用后仍展开；收起按钮和 Esc 生效 |
| 关闭／退出 | 关闭主窗回到球；明确退出才终止应用 |
| 状态保持 | 模块、便签选择、编辑内容在切换后保持 |
| 待办 | 新增、编辑、完成、恢复、删除和筛选真实生效，球数同步 |
| 网页 | 分组与搜索生效，删除分组保留网页，打开按钮实际打开保存的 URL |
| 便签 | 自动保存、切换前保存、退出重启后恢复；失败有具体提示且草稿仍在 |
| 手柄排序 | 待办、网页、便签、业务分组和两个窗口的模块导航均只从前方锚点拖动，正文点击／编辑不触发 |
| 跨分组 | 网页与便签可移动到空组、折叠组和筛选中不可见的组；分组本身可排序，未分组可排序但不能删除 |
| 顺序持久化 | 重启、窗口切换、便签编辑、待办完成／恢复和备份恢复都不破坏手动顺序，导航两窗一致 |
| 拖拽边界 | 搜索时业务锚点禁用；普通过滤可排序；滚动、取消、失败回滚和键盘控制正确，便签正文不丢失 |
| 导入导出 | 导出后恢复得到相同数据，取消不修改，非法文件不覆盖 |
| 屏幕与主题 | 多屏／缩放／Spaces 下窗口可访问，浅深主题一致，滚动和尺寸稳定 |
| 苹果风格与秩序 | 小球材质、面板层级和动作具有精致感；浅深主题下内容清楚，无装饰堆叠，布局与控件尺度统一 |
| 动效完整性 | 小球形态转换、导航、列表、勾选、数字及弹层均有连贯触感，按钮按下即时反馈 |
| 动效中断 | 快速切换、连点小球、连续完成／恢复待办时转向当前目标，最终形态正确，未保存内容不丢失 |
| 动效可用性 | 中文输入与文本选择不受影响，焦点不丢失；减少动态效果开启后功能完整，静置时无循环动画 |
| 最终交付 | `.app` 可在当前 Mac 直接启动，README 命令与实际一致 |

原生 Tauri 使用系统 WKWebView，必须在应用本身核实窗口和本地数据行为。原生 UI 操作优先使用现有可用的桌面检查工具；无法自动检查的系统行为交给用户执行明确步骤并记录结果，不能声称已验证。

实施时先完成 Rust 窗口与存储改动再进入连续 UI 测试。测试期间复用已有开发进程，不 kill、不改端口、不清缓存、不重装依赖。若之后的 Rust／配置改动必然导致应用或服务重启，先说明并等待用户决定重启时机。

## 批准后执行顺序

1. 重新读取本计划并初始化工程。
2. 完成存储与模块数据操作，校验关键持久化规则。
3. 完成原生三态窗口和状态交接。
4. 实现手写 UI、三个模块、手柄／跨组／导航排序、备份恢复、苹果风格的紧凑主题与丰富动效。
5. 完成允许范围内的 UI／原生验收，覆盖拖拽边界、动画中断及减少动态效果，修复发现的问题。
6. 构建本机 `.app`，交付源码说明、应用包和实际验收结果。
